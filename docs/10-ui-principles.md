# 10. 画面の決まり（2026-10-10 改訂）

画面を足す・直すときは、ここに合わせる。元になった考え方は2つ。

- **視認性と使い勝手**（2026-10-01〜03、日ノ出茶屋のハンディを現場向けに作り直したとき）
- **「AIで作った」と一目で分かる無難なデフォルトの見た目にしない**（2026-10-08 長谷川さんの指針。10-10 にこのシステムへ適用）

## 見た目の方向

**原因は、無難なデフォルトを全部そのまま採用すること。** 当てはまる特徴が1つ2つ残るのは構わない。いくつも重ならないようにする。

改修前に重なっていたもの: システムの書体のまま／白地に iOS の青（`#0a84ff`）のボタン／大きな角丸のカードが縦に並ぶ／
丸い札（ピル型）のボタン・タグ・カテゴリ切替の多用／左に色線を引いたカード／色つきの枠の中に白いカードを重ねる入れ子。

**すりガラスは全ての画面に残す**（2026-10-10 長谷川さん。同日いったんハンディと厨房を罫線だけの面にしたが、戻した）。

| 画面 | 決まり |
|---|---|
| 全画面共通 | 面はすりガラス（半透明の白＋白い縁＋上辺のハイライト＋やわらかい影）。背後に店の色の光（`.ambient-wash`。紫〜青のグラデーションにしない）。丸い札（ピル型）・左の色線・入れ子のカードは使わない |
| ハンディ `/handy`・厨房 `/kitchen` | 文字が読めるよう、面の白を濃いめ・縁をはっきり（`.handy`・`.kitchen-ui` の `--glass-strong`）。本当にぼかすのは、下を中身が流れるもの（ヘッダー・検索の帯・下のバー・シート）だけで、一覧の行やタイルは半透明の面だけにする（背後はなだらかな光なので見た目は同じ。古いスマホでも重くならない）。選択中は墨で塗り、強調色は主操作・提供前・数だけ |
| お客様の注文画面・管理画面 `/admin` | すりガラスのカード（角 22px）。ボタンや札は角丸の四角（8〜10px） |

共通: 書体は店ごとに指定する（システムの書体のままにしない）。絵文字・見出しの飾りアイコンは使わない。
文言は現場の言い方で、定型の言い回し（「シームレスに」「直感的な」など）は使わない。

## 店ごとに差し替えるもの（3ファイルだけ）

画面のコード（`app/`・`components/`・`lib/`・`store/`）は全店共通。店ごとの違いは次の3つに閉じ込める。
共通コードを別の店のリポジトリへ写すときは、この3つを除いてそのまま写せる。

| ファイル | 中身 | よこでじ版 |
|---|---|---|
| `app/fonts.ts` | 書体の読み込み（Google Fonts のURL） | Zen Kaku Gothic New（2026-10-10 長谷川さん「日ノ出茶屋の書体の雰囲気をよこでじにも」。屋号は筆文字にしない） |
| `app/brand.css` | 書体の割り当て、地・文字・強調・屋号の色、すりガラスの背後の光 | 紺 `#001543`・地 `#eef0f4`・文字 `#10131a`。光は紺と青緑に琥珀を少し |
| `lib/storeRules.ts` | 店の決まりで変わる振る舞い | ハンディからの卓の編集はオーナーだけ（DBの step22 と同じ） |

- 書体は表示時に Google Fonts から読む。ビルド時に取り込む方式（next/font）は、日本語の書体だと分割ファイルが数百あり、
  取得が1つでも失敗するとビルドが止まるので使わない
- 強調色は店の設定（テーマ色。`stores.theme`）が優先される。白い文字を載せるので、**薄い色を選ぶと読みにくくなる**
- 屋号（ハンディの卓一覧・管理画面のヘッダー）は `.brand-name`。店によっては筆文字や明朝にできる

## 視認性と使い勝手の決まり

1. **スタッフの画面は、見栄えより視認性**。暗い店内で、急いでいて、片手で使う前提で作る
2. **状態は色だけに頼らず、言葉を添える**（提供前／✓ 提供済み、空席、売切、受付中）
3. **強調色は大事なものだけ**に使う。全部に色を付けると、大事なものが埋もれる
4. **入力中のものを失わせない**。画面を下に引いても再読み込みにしない。読み直されても、送信前の内容は端末の控えから戻す
5. **言葉は現場の言い方に**。「セッションを締める」ではなく「卓を閉じる」。エラーは、何が起きて何をすればよいかを書く
6. **同じ見た目は1か所に持つ**。画面ごとに値を書き散らさない

| 対象 | 文字と大きさ |
|---|---|
| ハンディ・厨房（`components/handy/ui.ts`） | 文字は 14 / 16 / 18 / 20px の4段。品名・卓名など「読んで押すもの」は 18px 以上・太字。押すものは高さ 48px 以上、主操作は 56px。卓名や品名は明朝や筆文字にしない |
| 管理画面（`/admin`） | 12px 未満の文字は使わない。操作に関わる文字は 14px 以上。タブ・ボタンは高さ 40px 以上、＋−は 44px |
| お客様の注文画面 | 品名 17px・値段 15px・カテゴリの切替 15px。注意書き（変更・キャンセル、税込表示）も 12〜13px より小さくしない |
| 補助の文字の濃さ | 画面の種類ごとに `globals.css` で指定（`.handy` > `.staff-ui` > `.customer-ui`）。標準（60%）より濃い |

色はすべて `app/globals.css` のトークン（店の色は `brand.css` 経由）。すりガラスの値（`--glass` など）も同じ。注意（呼び出し・8分超の伝票・通知音ON・準備中）は琥珀、
急ぎは赤、提供済み・受付中は緑。売切は墨の印（強調色が赤系の店でも見分けがつくように）。

## 画面ごとの要点

- **お客様の注文画面**: カートは変わるたびに端末へ控え、再読み込みしても戻る（会計で卓が閉じたら捨てる。次に座った方には引き継がない）。
  売り切れの行き違いは「どの品が売り切れたか」を伝える。注文の状態は「準備中／提供済み」
- **管理画面**: ヘッダーは狭い画面でタブを1段ぶん使い、入りきらない分は横に流す。テーブル一覧は幅に合わせて2列〜。
  金額は注文のある卓だけ色を付ける。テーブル一覧の「全卓を一括清算」は、着席中の卓をまとめて会計して閉じる（閉店時など。
  注文のある卓は割引なし・チャージ料は設定どおり、注文の無い卓は受付の取り消し。1卓ずつ順に確定し、できなかった卓は名前を出す）。
  メニュー管理は「商品を追加」→「カテゴリ」→ 一覧の順（カテゴリの枠が一覧の下にあると見つからない）。
  まとめての追加は「商品を追加」の中の1行（開くと、1行に1品ずつ書く欄）
- **ハンディの店（`order_mode = 'handy'`）の管理画面**: 金額を持たない（会計はレジ）ので、金額・割引・税・チャージ料・Square・
  お客様の注文ページの写真・QRコードの設定は出さない。タブは「テーブル」「卓の履歴」、ボタンは「卓を閉じる」
- **ハンディ**: 卓一覧は、卓の数と画面の大きさに合わせて列の数とタイルの大きさを決める（`lib/handy.ts` の `fitTableGrid`。
  できるだけスクロール無しで全卓が見えるように。着席中は明るい白い面、空席は透けた面）。検索と種類の切替はスクロールしても上に残る。
  注文入力は、品名を押すと1つ入り、入れたあとは行の − ＋ でも数を合わせられる（お客様の注文画面と同じ。飲み方などの違いがある品は、組み合わせごとの行に − ＋）。
  数を合わせる組（瓶のグラスの数）がある品は、本体の数と付ける数を1つのシートで合わせてから入れる。おかわりの欄は1つの面の中を線で区切る
- **厨房**: 上部に「提供前 n件」。飲み方（一合・ロックなど）は品名と同じ強さの灰色の印、備考だけ赤

- **瓶とグラスは分けて表示する**（2026-10-10 長谷川さん「瓶グラスは誤解を生みます。分けて表示」）: グラスの数は品の数とは別の数（その注文の行ぜんぶでの数）。
  「1番搾りビン グラス3 ×2」と並べると1本あたりに読めるので、厨房の伝票・卓の画面・完了画面では「1番搾りビン ×2」「グラス ×3」と行を分ける
  （`lib/options.ts` の `splitCountOptions`）。注文入力では、品の行に本体の − ＋ と「グラスの数」の − ＋ を別々に出し、
  同じ品をもう一度足したときは別の行にせず本体もグラスも足し込む。レジ用の一覧にはグラスを出さない（レジに打つものではない）。
  管理画面の明細・履歴のように1行で書く所は「グラス 計3個」
- **注文の取消はハンディからもできる**: 卓の画面の「注文を取り消す」を押すと、各品に「取消」が出る。押すと確認のうえ1つ減らす
  （その伝票の品が無くなれば伝票ごと消える。厨房の伝票からも消える）。DB側は以前からある `cancel_order_item`（自店舗のスタッフのみ）
- **送信の完了画面**: 厨房へ送ったあと、「厨房へ送信しました」と送った内容を出す（`components/handy/SentView.tsx`）。
  そこから「卓一覧へ戻る／この卓を見る／続けて注文する」
- **送信が返ってこないとき**: 12秒待って返事が無ければ「送信を確認できませんでした」と出し、「もう一度」で送り直せる。
  送り直しは同じ合言葉で行うので、最初の送信が実は届いていても二重にならない（お客様の注文画面も同じ）
- **端末の「戻る」でアプリが閉じない**（`lib/backGuard.ts`）: ハンディ・厨房・管理画面は1ページの中で画面を切り替えているので、そのままだと
  戻るボタンでアプリが終わる。戻るを「いま開いているものを1つ閉じる」（確認 → シート → 注文入力 → 卓 → 卓一覧）に読み替える。
  履歴に足すのは画面に触れたとき（Chrome は触れずに足した履歴を飛ばすため）。触れずに戻るを続けて押すと、3回目あたりで閉じる
- **ホーム画面のアイコンは画面ごとに別**（`app/admin/pwa-icon`）: ハンディ＝スマホと注文の行、厨房＝料理にかぶせる蓋、管理画面＝4つの枠。
  地は店のテーマ色。設定で登録したアイコンの画像は管理画面だけに使う。すでにホーム画面に追加してある端末は、入れ直すと変わる
- ハンディの注文入力でも、左右スライドで種類を切り替える（お客様の画面・管理画面と同じ `useSwipePager`）。おかわり欄の「前回まで n」は出さない
- 管理画面のメニュー管理: 「メニューを削除」をやめて「メニューを編集」に。編集中は品名を書き換えられ、左の丸で選んで「選んだ品を削除」。
  ハンディの店（`order_mode = 'handy'`）では、写真の追加も出さない（注文画面に写真を出さないため）

用語: スタッフの画面は「提供前」「提供済み」（「作成中」「調理中」は使わない）。数は「点」。お客様の画面は「準備中」「提供済み」。

## DBの対応（step27）

- `menu_item_options.choice_group`: 同じ値のオプションは「どれか1つを必ず選ぶ」組。空なら個別のチェック
- `category_default_options` とトリガー: 「このカテゴリの品にはこのオプションを付ける」という店の決まり。品が増えたら自動で付く。
  決まりの変更は画面が無いのでSQLで行う（`supabase/step27-default-options.sql` の先頭に例）
- 既定値のまま（組なし・決まり0件）なら、今までの店の動きは変わらない
